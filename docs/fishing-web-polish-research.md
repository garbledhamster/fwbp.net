# Fishing web polish research

## What v31 does

The released game at `4399357` loads browser JavaScript modules from `index.html`. It draws the line with SVG and builds the picker, shop, and pause screen with DOM dialogs. The release has no Phaser dependency or web app manifest. The pause dialog already suspends the outing and restores focus on close. Use those controls and clock as the starting point for the new menu. [Site entry](../index.html) · [Fishing UI](../game/fishing.mjs) · [Outing clock](../game/suspension.mjs)

Campaign already converts swipe speed into line effort, but before a bite it moves depth by a fraction of each touch move. A down swipe has no release stroke in that phase. Hooking adds a separate aim test against the moving lure and rejects pointer movement over five CSS pixels. The base hook window opens 550 ms after the bite and closes at 2100 ms. Campaign skills, equipment, and the tutorial adjust it. The aim check, touch drift, and timing window can each explain a miss. The code establishes those conditions. A phone playtest can show which ones matter most to players. [Input and hook rendering](../game/fishing.mjs) · [Hook timing](../game/rules.mjs)

The fight already tracks paid-out line, pull, slack, and tension. Those values determine whether a line is safe to reel or snaps. The visible line uses an SVG curve with a 240 ms bend added by reel, loosen, or surge events. Its endpoint follows a mouth offset, but the fight does not turn the fish toward or away from the hole in response to the pull. An earlier standalone prototype, `outputs/fishing-line-physics-prototype.html` in the Campaign implementation workspace, simulated fish thrust and a tensile line at a fixed step, then drew a separate cubic curve. That prototype supports trying the tension model. It did not prove a simulated line shape. [Fight rules](../game/rules.mjs) · [Line drawing and fish positioning](../game/fishing.mjs)

## Controls and hook timing

Use the water as the tap target while seeking or setting the hook. Keep the tap separate from the swipe with one gesture recognizer. Track one primary pointer and decide on release whether it tapped, swiped, or canceled. Keep the starting bite and gesture together so a swipe in progress cannot hook a fish that bites after contact. Capture the pointer so release still arrives if the thumb leaves the water. Declare `touch-action` on the gameplay surface so the browser knows which pans to give to the game. Leave menu and shop scrolling native. Keep buttons and keyboard controls for players who use them. When testing a wider hook window or a short early buffer, keep the bite cue and the rule on the same timing source. Tune those values against real phone play. [W3C Pointer Events, direct manipulation](https://www.w3.org/TR/pointerevents/#declaring-direct-manipulation-behavior) · [W3C pointer capture](https://www.w3.org/TR/pointerevents/#pointer-capture) · [W3C pointer gestures guidance](https://www.w3.org/WAI/WCAG22/Understanding/pointer-gestures.html) · [Existing hook rules](../game/rules.mjs)

A downward swipe should add a bounded impulse based on release speed. Give a recognized slow swipe a minimum useful impulse so it still moves the lure. In a fight, map the same direction to giving line and map up to reeling. Reuse the current action rules and line strength until the control proof shows a reason to change them. Compare equal-distance slow and fast swipes. The faster stroke should carry farther or longer after release, and neither stroke should also register a tap. [Current gesture and effort handling](../game/fishing.mjs) · [Existing fight rules](../game/rules.mjs)

## Line and fish motion

Prototype a short chain of points with a pinned ice-hole end and a lure or fish-mouth end. Integrate point motion from current and previous positions, apply damping, and iterate neighboring distance constraints at a fixed time step. Carry forward the leftover time and cap work after a suspended tab or long frame. The chain can bow when it has slack and tighten when the endpoints pull apart. When both endpoints are pinned, keep the simulated chain length at least as long as the distance between them. Keep the chain in one world coordinate space and transform it through the camera once. Reset it on a new hole, a large discontinuity, or a change of coordinate space. These are proposed game choices. The sources describe the integration, distance constraints, attachment, and time-step behavior they build on. [Jakobsen, §§2 and 4](https://www.cs.cmu.edu/afs/cs/academic/class/15462-s13/www/lec_slides/Jakobsen.pdf) · [Müller et al., §3](https://matthias-research.github.io/pages/publications/posBasedDyn.pdf) · [Bender, Müller, and Macklin, §5.8 and Figure 14](https://matthias-research.github.io/pages/publications/PBDTutorial2017-CourseNotes.pdf) · [Fiedler, Fix Your Timestep](https://www.gafferongames.com/post/fix_your_timestep/)

Use the existing fight's pull, slack, and tension as shared inputs to fish motion and line drawing. Feed changes in the fish's position and line payout into the chain so its response comes from moving endpoints and changing slack. During a run, let the fish aim along the escape direction. When reeling takes up slack, turn the fish toward the hole as tension builds. Rotate and mirror around the mouth, and use that same mouth point as the last line point. This keeps the hook attached as the fish turns. Measure that endpoint agreement through a run, a reel, and a resize. Check that slack can disappear before load builds and that the line falls still when the player pauses. ## Phaser and the installed web game

Three implementation paths fit the code to different degrees:

- Keep the SVG renderer and add the line simulation. This is the shortest way to validate how the new gestures and line feel.
- Give Phaser a Campaign water scene that renders the line, lure, and hooked fish from the existing rules and a line simulation module. Keep controls, menus, and the shop in the DOM. This gives Phaser ownership of visible gameplay in the part Joe asked to improve and limits changes to saved progress and other modes.
- Rebuild the entire web game as a Phaser app. This is a separate migration across the lake, assets, other modes, and release process. The new gestures and line physics can be tested before taking on that work.

If this update should use Phaser, I recommend the Campaign scene. Phaser Graphics can draw the computed point chain. The scene should receive state and produce views, with one owner for player input and the rules outside the scene. Phaser publishes a TypeScript and Vite template. Integrating a build into this static site adds a packaging decision. Verify the renderer and assets in the numbered release as well as the root site. [Phaser scenes](https://docs.phaser.io/phaser/concepts/scenes) · [Phaser Graphics](https://docs.phaser.io/phaser/concepts/gameobjects/graphics#drawing-a-series-of-lines) · [Phaser input](https://docs.phaser.io/phaser/concepts/input) · [Official Phaser Vite TypeScript template](https://github.com/phaserjs/template-vite-ts) · [Current snapshot file list](../gitpush)

Give the website's Play link and the installed app the same direct game entry. The manifest's `start_url` sets the preferred launch page, `scope` covers the app routes, and `display: standalone` requests an app window without the usual URL bar. Check launch from an installed home-screen icon on a phone. Put the release version in the game menu and verify that it matches the numbered snapshot. Reuse the pause dialog's existing suspension and focus return. If the new panels use tab semantics, wire the arrow keys and selected panel state to match. [W3C Web Application Manifest](https://www.w3.org/TR/appmanifest/) · [W3C modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) · [W3C tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) · [Release script](../gitpush)

The current Campaign stores progress in IndexedDB. WebKit documents that iOS 17.2 copies login cookies on install and keeps other website data separate between the browser and Home Screen app. Test a saved Campaign in Safari, then install and open the app and check what it can resume on the target phone. If the phone starts with an empty profile, explain the separate save before players install. Preserving continuity between the two contexts would need an explicit transfer or sync feature. [Campaign profile storage](../game/profile.mjs) · [WebKit, login cookies and Home Screen storage](https://webkit.org/blog/14787/webkit-features-in-safari-17-2/#login-cookies)

## First phone check

Open the game from the site and from its installed icon. Start fishing from the primary menu action, tap away from the lure, hook on the bite cue, swipe down slowly and quickly, and reel a hooked fish to the hole. Watch for extra actions after a swipe, a hook that leaves the fish's mouth when it turns, and a clock that advances behind the pause menu. Run the same control and timing checks with a mouse and keyboard. Ask the two children to try the phone build without directions before treating ease of use as verified.
